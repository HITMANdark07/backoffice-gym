> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the M3 demo site live at `https://backoffice-gym.vercel.app` on Vercel + Supabase, with rate limits, a locked-down database, CI, and an entry on the portfolio.

**Architecture:** The code side makes production behaviour switchable by environment variables (rate limiter, pool size, canonical URL) and adds a row-level-security backstop migration, GitHub Actions for CI and migrations, and a Vercel config with a daily cron. The dashboard side (Supabase project, Vercel import, secrets) is done by the user from `docs/deploy.md`; Claude never sees connection strings. After deploy, a smoke test checks the live site, then the portfolio gets a project page with a real-data demo of one recorded run.

**Tech Stack:** Next 16.2.4 on Vercel (region `bom1`), Supabase Postgres (Mumbai, `ap-south-1`) through Supavisor, Prisma 7.10.1 with `@prisma/adapter-pg`, Hono 4.13.13, GitHub Actions, Vitest 2, the portfolio's Next 16 static site.

**Spec:** `docs/superpowers/specs/2026-10-22-backoffice-gym-design.md` (§6 rate limits and expiry, §10 deployment, §12 security; M5 line in §13).

## Global Constraints

- Never read, print or modify any `.env` file. Never `echo`/`export` secrets. Connection strings are entered by the user in the Supabase, Vercel and GitHub dashboards only.
- Live URL: `https://backoffice-gym.vercel.app`. Vercel project name `backoffice-gym`, root directory `apps/web`.
- Rate limits (spec §6): 30 episodes and 600 steps per IP per hour, already in `DEFAULT_LIMITS`. On in the cloud only (`BACKOFFICE_GYM_RATE_LIMIT=on`), off locally.
- Anonymous episodes expire after an hour; `GET /api/health` expires up to 100 and prunes old rate-limit windows.
- Postgres schema `backoffice_gym`; 18 tables today. The app connects as the table owner.
- Node ≥ 20.19, pnpm 10.33.0 (`packageManager`), Postgres 17 locally and in CI.
- Pushes to GitHub and the portfolio push need the user's go-ahead at that step.
- Portfolio copy: real numbers only, each traceable to data; never use the name "Januji" (say "an AI companion app"); don't commit the portfolio's pre-existing `CLAUDE.md` change.
- No paid model runs.

## Review Focus

1. **Client IP spoofing.** A visitor who sends their own `x-forwarded-for` must not get a fresh rate-limit bucket on Vercel. Expect `x-real-ip` (set by Vercel) to win over `x-forwarded-for`; test in Task 1 pins the precedence.
2. **Production build with no site URL.** A production build without `NEXT_PUBLIC_SITE_URL` would ship `localhost` canonicals, sitemap and OG URLs. Expect the build to fail loudly; test in Task 3.
3. **Other database roles.** Supabase's `anon`/`authenticated` roles (Data API) must not read any table even if the schema is later exposed. Expect zero rows for a non-owner role; test in Task 4.
4. **Rate limiter off by default.** Local dev and CI must not need a `rate_limits` write per request, and a typo in the flag must not silently enable it. Expect only the exact value `on` to enable it; test in Task 2.
5. **Pool size env junk.** `BACKOFFICE_GYM_DB_POOL_MAX` set to `''`, `abc`, `0` or `3.5` must fall back to the driver default rather than crash or open 0 connections; test in Task 2.

`packages/api/src/client-ip.ts`:

```ts
/**
 * The visitor's address for rate limiting. On Vercel, x-real-ip is set by the platform; x-forwarded-for is
 * the fallback for other proxies. Requests without either share one "unknown" bucket.
 */
export function clientIpFromHeaders(get: (name: string) => string | undefined): string {
  const real = get('x-real-ip')?.trim();
  if (real) return real;
  const first = get('x-forwarded-for')?.split(',')[0]?.trim();
  return first || 'unknown';
}
```

```ts
/** The canonical origin for links, the sitemap and OG images. Production builds must set NEXT_PUBLIC_SITE_URL. */
export function resolveSiteUrl(env: { NEXT_PUBLIC_SITE_URL?: string; VERCEL_ENV?: string }): string {
  const url = env.NEXT_PUBLIC_SITE_URL?.trim().replace(/\/+$/, '');
  if (url) return url;
  if (env.VERCEL_ENV === 'production') {
    throw new Error('NEXT_PUBLIC_SITE_URL must be set for production builds: canonical URLs, the sitemap and OG images use it.');
  }
  return 'http://localhost:3100';
}

  url: resolveSiteUrl({ NEXT_PUBLIC_SITE_URL: process.env.NEXT_PUBLIC_SITE_URL, VERCEL_ENV: process.env.VERCEL_ENV }),
```

`packages/db/prisma/migrations/20261024120000_enable_rls/migration.sql`:


```ts
/** One real recorded BackOffice Gym run, generated by scripts/build-backoffice-run.mjs. */
import data from "../generated/backoffice-run.json";

export interface RunStep {
  n: number;
  tool: string;
  args: string;
  ok: boolean;
  /** Reward if the agent had stopped right after this step. */
  reward: number;
  /** Rows this step changed in the store database. */
  changes: number;
}

export interface RunCheck {
  id: string;
  kind: "required" | "forbidden";
  detail: string;
  passed: boolean;
}

export interface BackofficeRun {
  run: { id: string; model: string; task: string; taskTitle: string; seed: number; reward: number; url: string };
  steps: RunStep[];
  checks: RunCheck[];
}

export const backofficeRun = data as BackofficeRun;

/** Index of the first step whose reward is lower than the step before it, or -1. */
export function firstRewardDrop(steps: Pick<RunStep, "reward">[]): number {
  return steps.findIndex((s, i) => i > 0 && s.reward < steps[i - 1].reward);
}
```
